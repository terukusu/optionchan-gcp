# 過去データの欠け（#110）

## このページについて

旧系（`functions/jpx_loader.py`、2018-10〜2026-10）の JPX の解析の不具合などでできた過去データの欠けと、その後の作り直し（#111・#114）の記録。今の表のどこに何が無いかを、欠けごとにまとめる。

- 行の作り直しの手順は runbook に残す（docs/runbook.md の「DataCube の歩み値での穴埋め（#111）」「DataCube の歩み値での行の作成（#114）」）。このページは結果と今の状態だけを書く
- 欠けの区間の一覧は `sql/gaps/gaps.sql` で出す（下の「欠けの一覧の SQL」）。このページには要約（件数・期間・割合）だけを書き、生の結果・行の値は貼らない。#111・#114 の作った値は J-Quants DataCube（自己使用のライセンス）から作ったので、値も載せない
- 欠けを埋めた・新しく見つけたときは、このページの「欠けの一覧」と「結果の要約」を直す（`gaps.sql` を流し直して数え直す）

## 欠けごとの詳細

### 欠け 1（2022-09-14 15:16 〜 2023-04-25 13:35）

- 旧系はこの間ずっと解析に失敗し、3 表の行が 1 つも無かった。旧系の欠けたページは GCS に残っていない（解析の後に保存していた）
- #114 で DataCube の歩み値から option・future・ingest_runs の行を作った。spot は元のデータが無いので作っていない
- 作ったスナップショットは約定のあった分だけ。作っていない分（立会中の分の約 4%）は、米国の祝日の夜など約定の無い分に集中している
- 手順・作り方・合い方は runbook の「DataCube の歩み値での行の作成（#114）」

### 欠け 2（2023-04-25 13:42 〜 2023-05-08 16:31）

- 行・気配・気配の IV・`iv` は旧系の JPX の値がある。無かったのは option の `price`・`price_time` だけ
- #111 で、取引高（`volume`）が取引日の約定の累計と一致する約定で埋めた。印は `parser_version = 'legacy-fill111-1'`
- 行の欠けではないので `gaps.sql` には出ない
- 手順は runbook の「DataCube の歩み値での穴埋め（#111）」

### 欠け 3（〜 2024-08-06 12:25）

- 現物か先物の前日比が ±1,000 以上になるとページの値にカンマが付き、旧系の解析が落ちた。前日比が 1,000 に届いた時点で区間が始まり、下がったところで終わる
- 修正が本番で効いたのは 2024-08-06 12:25。それより後には起きない
- 2020 年（55 区間）と 2024 年（18 区間）に多い
- #114 で作った（欠け 1 と同じ作り方・同じ列）。歩み値を買った月の区間だけが対象。買っていない月の区間は残る

### 2021-07 の停止（2021-07-26 17:24 〜 2021-07-28 02:53）

## 欠けの一覧の SQL

`sql/gaps/gaps.sql` は読み取りだけ（表を作らない・書かない）。旧系のスナップショットが途切れた区間ごとに 1 行を返す。

### 流し方

全期間で流す（範囲の外にはみ出す区間は出さないので、範囲を切ると端の区間が抜ける）。`P`・`L`・`q`・`qr` は runbook の「過去データの移行（#12）」の「変数」と同じ。結果は作業ディレクトリに置き、リポジトリ・Issue に貼らない。

```sh
rgap() { sed -e "s/[$]{project}/$P/g" -e "s/[$]{dataset}/optionchan_tokyo/g" sql/gaps/gaps.sql; }
rgap | qr '2018-10-01 00:00:00+00' '2026-10-17 00:00:00+00' --location=$L --format=csv --max_rows=100000 \
  --maximum_bytes_billed=5000000000 > $WDIR/gaps.csv
```

- スクリプトなので、bq は CSV の前に文を出す。結果はヘッダ `prev_at,next_at,` の行から読む
- 処理量は 約 0.2GB（2026-10-18 の実測。`ingest_runs`・`future_price`・`spot_price` の必要な列）。`option_price` は読まない

### 区間

- 旧系のスナップショット（`ingest_runs` の `trigger = 'legacy_import'`）の隣り合う 2 つ（`prev_at`・`next_at`）の間が 15 分以上あく区間（#114 の `hole_gap_minutes` と同じ）
- 区間の中の分の終わり c（`prev_at < c < next_at`）ごとに、分 [c − 1 分, c) の始まりで立会中かどうかを数える
- 立会中の分が 15 分以上ある区間だけを出す（立会の終わりの直前の数分の空白などは出さない）

### 立会の時間

先物の立会の時間で数える（旧系は先物でページが変わる）。取引日は、土日でなく、取引カレンダー `trading_calendar_latest` で休業日でない日（祝日取引の日は取引日）。

| | 〜 変更日の前 | 変更日から |
|---|---|---|
| 日中 | 8:45〜15:15 | 8:45〜15:45（2024-11-05 から） |
| 夜間の始まり | 16:30 | 17:00（2024-11-05 の夕方から） |
| 夜間の終わり | 翌 5:30 | 翌 6:00（2021-09-21 の夕方から） |

- 夜間は夕方の日（取引日）から数える。土曜の朝は金曜の夜間
- 2021-09-17（金）の夜間は市場の休みなので数えない
- オプションの日中の始まりは 2021-09-21 から 9:00 → 8:45。旧系は先物でページが変わるので、その前も 8:45 から数える
- 出典: 証券会社の告知（2021-09 の J-GATE 3.0 への移行、2024-11 の立会時間の延長）と、旧系のスナップショットの時刻（変更日の前後で日中の最後 15:16 → 15:46、夜間の最初 16:30 → 17:00、夜間の最後 05:26 → 05:56）。JPX のサイトの資料は読めなかった

### 原因（この順に最初に当たったもの）

| 原因 | 規則 |
|---|---|
| `bug_format` | 欠け 1。区間が 2022-09-14 15:16 〜 2023-04-25 13:35 と重なる |
| `bug_comma` | 欠け 3。`prev_at` が 2024-08-06 12:25 より前で、前か後のスナップショットの現物・先物の前日比の絶対値の最大が 700 以上 |
| `no_change` | 仕様。前と後のスナップショットの先物の値が同じ |
| `unknown` | それ以外（停止・取得の失敗など。前後の先物の行が無い区間も） |

- `bug_comma` のしきい値 700 は推定。区間は前日比が 1,000 に届いて始まり、下がって終わるので、前後のスナップショットは 700〜999 になりやすい。直前だけで見ると 69 区間で、直後で見る区間（下がって終わる区間）が抜けるので、前後で見る
- 限界: 前日比が 700〜999 のまま普通に取れた後に別の原因で止まった区間も `bug_comma` になる。前後で同じ値に戻った活発な区間も `no_change` になる

### 今の状態

| 状態 | 規則 |
|---|---|
| `none` | #114 の作ったスナップショット（`ingest_runs` の `trigger = 'legacy_fill114'`）のある分が 0 |
| `filled` | 作ったスナップショットのある分が立会中の分の 90% 以上 |
| `partial` | それ以外 |

- #114 は約定のあった分だけ作るので、埋めた区間でも約定の無い分は残る。欠け 1 の作っていない分（約 4%）は約定の無い分なので、90% を `filled` の線にした
- 原因と状態は別に決める（`unknown` の区間も #114 が作っていれば `filled`）

### 出す列

`prev_at`・`next_at`（TIMESTAMP）、`prev_jst`・`next_jst`（JST の DATETIME）、`gap_minutes`、`session_minutes`（立会中の分）、`built_minutes`（作ったスナップショットのある分）、`cause`、`status`、`max_abs_diff`（前後のスナップショットの前日比の絶対値の最大。旧系の JPX の値）。

### 出ない区間

- 立会中の分が 15 分未満の区間（全期間で 1,357 区間。多くは立会の終わりの直前の、値の動かない数分）
- 欠け 2（行の欠けではない。期間は上の表）

### 表にしない理由

旧系は止めていて（#14）、過去の旧系の行はもう増えない。一度流して要約をこのページに書けば足り、本番の DDL・定期実行が要らない。ビューアーが一覧を使うときの持ち方は別 Issue で決める。
