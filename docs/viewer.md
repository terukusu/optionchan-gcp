# ビューアー

日経225 オプションの IV を見るウェブアプリ（`apps/viewer`、#13・#52。Python 3.13・uv・Flask）の使い方。Cloud Run `viewer`（asia-northeast1）で IAP の後ろに置き、BigQuery の `optionchan_tokyo`（最新版のテーブル関数・1 時間足・30 日固定の表。[data.md](data.md)）を読むだけで、書き込みはしない。

- ページは `/`（トップ）・`/atm_iv`（ATM IV の推移）・`/smile`（スマイルカーブ）の 3 つ。画面が読むデータは CSV の API（下の「データの API」）
- 時刻の表示はすべて JST。API の時刻は UTC（UNIX 秒か `YYYY-MM-DD HH:MM:SS+00:00`）
- 旧ビューアー（`appengine/` と旧 HTTP 関数。旧系）とは独立している。`/smile_data`・`/atm_iv_data` は旧ビューアーと同じ URL・同じ CSV の形式で残している（旧型の ATM 推移のページとその API は移していない。#58）
- 用語（限月・ATM・OTM・mid IV・期近つなぎ など）は [glossary.md](glossary.md)
- 事実の正はコード: ルートは `apps/viewer/src/optionchan_viewer/app.py`、引数の検査は `apps/viewer/src/optionchan_viewer/api.py` の `parse_*`、上限・既定値は `apps/viewer/src/optionchan_viewer/settings.py`、CSV の列は `apps/viewer/src/optionchan_viewer/csvfmt.py`、画面は `apps/viewer/src/optionchan_viewer/templates/` と `apps/viewer/src/optionchan_viewer/static/`

## 開き方

- URL は Cloud Run `viewer` のサービスの URL（`run.app`）。IAP（Cloud Run への直接設定）が掛かっていて、開くと Google のログインを求められる。URL はプロジェクト番号由来の文字列を含むので Issue・PR に貼らない。調べ方は `docs/runbook.md` の「ビューアー（#13）」の「変数」（`gcloud run services describe viewer … --format='value(status.url)'`）
- 開けるのは bootstrap の変数 `viewer_iap_members`（`user:<メール>` か `group:<メール>`。`domain:`・`allUsers`・`allAuthenticatedUsers` は validation で拒否）に入れたアカウントだけ。追加・削除は bootstrap の apply（[setup.md の「4. ビューアーの IAP」](setup.md#4-ビューアーの-iap)、runbook の「ビューアー（#13）」の「更新」）
- アプリには認証も回数制限も無い。IAP を外す・`allUsers` に `run.invoker` を付けるなどで公開しない（URL を知っている誰でも BigQuery のクエリを回せて課金が増える。[runbook の「ビューアー（#13）」](runbook.md#ビューアー13)）
- 手元で起動するときは BigQuery を読み取りだけで使う（[development.md の「ローカルでの起動」](development.md#ローカルでの起動)）。環境変数は下の「設定（環境変数）」

## ATM IV（/atm_iv）

ATM の IV の推移をローソク足か折れ線で描く（#68。チャートは TradingView Lightweight Charts）。データは `/atm_iv_bars`。

### 選択肢

| 欄 | 選択肢 | 既定 | 中身 |
|---|---|---|---|
| 足 | 1分・5分・15分・1時間・日足 | 1時間 | 5分・15分足は 1 分足を読んで画面で束ねる（1 分・5 分・15 分の切り替えでは読み直さない）。日足は取引日ごと（夜間は次の取引日。休業日は取引カレンダー `trading_calendar_latest`）で、画面の日付も取引日（#124） |
| 限月 | 0・1・期近つなぎ・30日固定 | 0 | 0・1 は今日から数えて何番目の限月（0 が期近）。期近つなぎ・30日固定は下に |
| IV | mid（気配の中値）・約定 | mid | mid IV =（bid_iv + ask_iv）/ 2。分足は最新版の ATM の put から（#93）、1 時間足・日足は mid の 1 時間足 `atm_mid_iv` から（#98）。約定は約定 IV（`iv`）で、分足は最新版の ATM の put から、1 時間足・日足は 1 時間足 `atm_iv` から。30日固定では使わない（欄を選べなくする） |
| 表示 | ローソク足・折れ線 | ローソク足 | 折れ線は終値を結ぶ。切り替えは描き直すだけで読み直さない |
| 日付（JST） | 日付の入力 | 空 | 下の「日付へ移動」 |

足・限月・IV を変えても、表示している時間の範囲を保つ（その範囲を読み直す）。

### 期近つなぎ（`n=roll`、#101）

期近の ATM IV を限月の乗り換えでつないだ長期のチャート。日足なら 2018-10 まで遡れる。

- 乗り換えの規則: 足の取引日（夜間は次の取引日）が期近の最終取引日の 5 営業日前に達したら（残存営業日数 = その取引日より後で最終取引日以下の営業日の数が 5 以下）2 限月へ乗り換える。日数はコードの定数 `ROLL_BUSINESS_DAYS`（環境変数ではない）。営業日は土日・取引カレンダーの休業日を除く日で、祝日取引の日は営業日
- 乗り換えは取引日の境目（夜間の始まりの 17:00 JST）に来る。選んだ限月の値が無い足・IV が 0 以下の足は除き、期近へ戻さない（その時間は線が途切れる）
- 乗り換えた足に印（例: 「12月限」）を付け、凡例にカーソルの足の限月（「12月限（最終取引日 YYYY-MM-DD）」）を出す
- 残存の短い期近は IV が高く出るので、乗り換えの所に段差が出る（補正はしない）

### 30日固定（`n=cm`、#100）

限月ごとにフォワードの位置で補間した ATM IV から、満期 30 日に補間した IV。ATM の行使価格の乗り換え・限月の乗り換えによる段差が無い。計算は [data.md の「30 日固定の ATM IV の計算」](data.md#30-日固定の-atm-iv-の計算)。

- 値は取り込み 1 回ごとに 1 つ。分足は 1 分 1 本、1 時間足・日足はそれを束ねたもの
- 表 `atm_cm_iv`（定期クエリ `atm-cm` が作る）と、まだ表に入っていない分（最大 3 日）を生の気配から同じ SQL で計算したものをつなぐ
- 気配の中値から作るので IV（約定 / mid）は選べない。凡例の先頭に「30日」と出す

### 読み込む範囲

期間の選択は無い。チャートの表示範囲（スクロール・拡縮）で読む範囲が決まり、端に近づくとその外側を追加で読む（#77）。

- 最初はサーバーの既定の範囲を読む（分足は最新のスナップショットの前日の UTC の 0 時〜今、1 時間足は 10 日、日足は 100 日）
- 読み込み中はチャートを薄くしてスピナー（最初・切り替え）か、端に「前のデータを読み込み中…」「後のデータを読み込み中…」を出す。失敗したら理由と「再試行」を出す
- 取りすぎ防止（画面の中だけ。ページを読み直すと戻る）: 同時に読むのは 1 本、連続するスクロール・拡縮は 250 ms まとめる、足・限月ごとに読んだ範囲を覚えて読み直さない。足・限月ごとに覚える日数は分足 9 日・1 時間足 400 日、分足をこの画面で読む日数の合計は 24 日まで。データの無い範囲が 3 回続いたらそれより前は無いとみなす
- 分足は直近 31 日分まで（それより前は 1 時間足・日足で）

### 日付へ移動

「日付（JST）」の欄で日付を選ぶと（打ち込みは打ち終わってから）、選んでいる足のままその日のまわりへ移動する。

- その日の 12:00 JST を中心に、1 分足は ±2 時間・5 分足は ±6 時間・15 分足は ±18 時間・1 時間足は ±3 日・日足は ±60 日を読み直す。そこから左右へスクロールすると続きを読む
- 選べるのは 2018-10-19（欄の下限）〜今日（JST）。範囲の外を打ち込むと「日付を 2010-01-01〜今日の範囲で入れてください」を出す。分足は直近 31 日までのまま
- 移動した範囲に足が無ければ、それより前を探しに行かずに止まる（遠くの足が出て、移動した日付から外れないように）

### 足が 0 本のとき

チャートの真ん中に理由と、表示できる選び方のボタンを出す。

- 限月 0・1: 今日から数えた限月なので、過去の日付へ移動するとその限月の足が無い →「期近つなぎで表示」
- mid: 気配の無い期間がある →「約定で表示」
- それ以外は「データがありません」

### 欠けの帯と印（#123）

過去データの欠け（[data-gaps.md](data-gaps.md)）を足に重ねて出す。

- ページを開いたときに `/data_gaps` を 1 回だけ読む（足・限月・IV の切り替え・スクロールでは読まない）。区間の時刻はコードに持たず、表 `data_gaps` の値を使う
- 約定（限月 0・1・期近つなぎ）では、#114 で約定から作った区間の足の背景に帯を付ける。作れなかった区間と、mid・30日固定のすべての区間（作った行に気配が無い）は足の下に ■ を付ける
- 凡例にカーソルの足の区間（種類と期間）を出し、mid・30日固定で足が 0 本のときは説明に区間の期間を足す。区間が 1 件以上あるときはチャートの下に帯・■ の説明を出す
- `/data_gaps` が読めない・空なら帯・印を出さずに描く。表は所有者が runbook の「欠けの一覧の表 data_gaps（#123）」の手順で入れる

### 凡例・時刻

- 凡例はカーソルの足の時刻（日足は日付だけ）と O・H・L・C。mid なら先頭に「mid」、30日固定なら「30日」
- チャートの目盛り・ラベルは JST。データのある足だけを並べるので、取引の無い時間・週末・休日は詰まる

## スマイルカーブ（/smile）

1 時点の行使価格ごとの IV を、1 限月・2 限月で描く（#79。チャートは Chart.js）。データは `/smile_snapshot`。

### 曲線

- 表示「OTM合成」（既定）: ATM より下は put・ATM 以上は call の mid IV を線、bid〜ask の IV を縦のひげ、約定の IV を点で描く
- 表示「call・put別」: call と put を別の線にする
- 横軸は行使価格（値に比例）。初めの横の範囲は描いている限月の行使価格の全体（#127）
- 曲線の規則はサーバーの `apps/viewer/src/optionchan_viewer/smile.py`: IV（`iv`・`bid_iv`・`ask_iv`）の 0 以下は欠損、mid IV は bid・ask の IV が両方あるときだけ、ATM は限月ごとに put で `is_atm` の行の行使価格の最小、OTM 合成に使うのは put で行使価格 < ATM・call で行使価格 >= ATM（ATM ちょうどは call）
- 約定の IV の点は約定からの経過で 4 段（5分以内・30分以内・2時間以内・2時間より前・時刻不明）に塗り分ける（濃いほど最近）。「経過時間」をオンにすると経過（分）を右軸に点線で描く
- 「1限月」「2限月」のチェックで描く限月を選ぶ。ATM の位置に縦線とラベルを描く

### 操作

- マウス: ホバーで行使価格の詳細、ドラッグでスクロール、ホイールで拡大縮小
- スマートフォン: 1 本指の横のドラッグでスクロール、長押しで行使価格を選び、そのままなぞると選び直す（端まで行くと表示範囲を送る）。タップでも選べる。2 本指で移動・ピンチで拡大縮小、縦のスワイプでページをスクロール
- 拡大縮小・スクロール・表示の切り替え・時点の固定ではサーバーに要求しない
- カーソルの行使価格の値（限月 × call / put ごとに mid・bid・ask の IV、約定IV・約定・約定時刻・気配）をチャートの上に出す。「表示をリセット」で横の範囲を初めに戻す

### 時点

- 「最新」・前後のステップ（−1日・−1時間・−10分・−1分・+1分・+10分・+1時間・+1日）・「日時（JST）」の入力と「表示」で時点を動かす。表示している時点は見出しの横に「… JST 時点」と出す
- 「−」方向は指定した時刻以前で最新のスナップショット、「+」方向はその時刻以後で最初のスナップショット（#80）。取引の切れ目（引け〜次の取引の開始・週末・休業日）の手前から「+1分」を押すと、1 回で次の取引の最初の時点に移る。それより新しいものが無ければ最新を見せ、「これより新しいデータはありません」を出す
- 日時は 2010-01-01 以降（それより前は「日時は 2010-01-01 以降を入力してください」）
- 「この時点を固定」で今の時点を比較用に残し（点線）、別の時点と重ねて比べる。「固定を解除」で消す
- 一度読んだ時点は画面で覚えて読み直さない（「最新」は 60 秒まで）。時点の移動は 250 ms まとめて 1 本にし、前の要求は中断する
- 1 ページで出す要求は 20 本まで（中断・再試行も数える）。超えると「この画面で読み込めるのは 20 時点までです（ページを読み直してください）」

### 注記

グラフのすぐ上に出す（#127）。

- #114 で約定から作った時点（`/smile_snapshot` の 1 行目の `source` が `fill114`）:「この時点は取得できなかったため、別に購入した約定データから作り直しています。売り気配・買い気配は無く、点（約定の IV）だけを表示しています」
- 気配の無い時点:「気配がありません（取引時間外）。約定の IV の点だけを表示しています」
- OTM 合成で限月の ATM が分からないとき:「N 限月の ATM が分からないので OTM 合成を描けません」
- 読み込みに失敗したら理由と「再試行」を出す。429 なら「今日の読み込みの上限に達しました（日本時間の 0 時に戻ります）」（`/atm_iv` も同じ）

## データの API

画面が読む CSV の API。すべて GET で、IAP の後ろにある（ブラウザで開いた画面からだけ呼ぶ想定）。

共通:

- 成功は 200・`text/csv; charset=utf-8`・`Cache-Control: no-cache`。ヘッダ行は無い。改行は `\n`、値の無いセル（NULL）は空、時刻は列ごとに UTC の UNIX 秒か `YYYY-MM-DD HH:MM:SS+00:00`
- 引数の形が不正なら 400（本文 `bad request`。BigQuery は呼ばない。応答・ログに入力値を出さない）。1 日のクエリ量の上限に達したら 429（`daily limit`。下の「設定（環境変数）」の `DAILY_BYTES_BILLED`）。探す範囲にデータが無いとき `/smile_data` は 503（`no data`）。BigQuery の失敗は 500（`internal error`）
- 数値の引数は数字だけ（符号・小数・空白・末尾の改行は 400）。名前の引数は決まった値との完全一致（大文字・空白は 400）

### `/atm_iv_bars`（`/atm_iv` が読む）

`/atm_iv_bars?tf=&n=&iv=&start=&end=`。足 `tf` の ATM IV の OHLC。

| 引数 | 値 | 既定 |
|---|---|---|
| `tf` | `1m`・`5m`・`15m`・`1h`・`1d` | `1h` |
| `n` | `0`・`1`（今日から数えた限月）・`roll`（期近つなぎ）・`cm`（30 日固定） | `0` |
| `iv` | `trade`（約定 IV）・`mid`（mid IV） | `trade`（画面は `mid` を付けて読む）。`n=cm` では検査だけして使わない |
| `start`・`end` | UTC の UNIX 秒。足の始まり（`started_at`）が `[start, end)` の足を返す。両方か両方なし | なしなら足ごとの既定の範囲 |

期間（`settings.py` の `BARS_RANGE`。`start >= end`・片方だけ・上限を超えると 400）:

| 足 | 既定の範囲（`start`・`end` なし） | 1 回の上限（`end − start`） | `start` の下限 |
|---|---|---|---|
| `1m`・`5m`・`15m` | 最新のスナップショットの 1 日前の UTC の 0 時〜今 | 3 日 | 今の 31 日前の UTC の 0 時 |
| `1h` | 今の 10 日前の UTC の 0 時〜今 | 100 日 | 2010-01-01 |
| `1d` | 今の 100 日前の UTC の 0 時〜今 | 400 日 | 2010-01-01 |

- 未来の `end` は今に縮める（400 にしない）
- 読んだ範囲を応答のヘッダ `X-Bars-Start`・`X-Bars-End`（UTC の UNIX 秒）で返す。画面はこれで読んだ範囲を覚える
- CSV の列は `open,high,low,close,started_at`（`started_at` 昇順）。値の無い足は除く。行が無ければ空の 200
- `n=roll` だけ 6 列目に `last_trading_day`（その足の限月の最終取引日 `YYYY-MM-DD`）を足す
- 日足の `started_at` はその取引日の 00:00 JST
- 分足は最新版の ATM の put から 1 分足を作る（5・15 分足はサーバーでも束ねる）。1 時間足・日足は 1 時間足（`atm_iv`、`iv=mid` なら `atm_mid_iv`）と、まだ 1 時間足になっていない分（最大 3 日）を生データから補ったものから

### `/atm_iv_data`（旧ビューアーと同じ形式）

`/atm_iv_data?d=&n=`。ATM IV の 1 時間足。

| 引数 | 値 | 既定 |
|---|---|---|
| `d` | 日数 `1`〜`100`。今の `d` 日前の UTC の 0 時から今まで | `7` |
| `n` | `0`・`1`（`roll`・`cm` は受け付けない） | `0` |

- CSV の列は `/atm_iv_bars` と同じ `open,high,low,close,started_at`（`started_at` 昇順）
- 引数 `iv` は無い（約定 IV だけ）

### `/smile_snapshot`（`/smile` が読む）

`/smile_snapshot?at=&dir=`。1 時点のスマイルの行。

| 引数 | 値 | 既定 |
|---|---|---|
| `at` | UTC の UNIX 秒。2010-01-01 より前は 400、未来は今に縮める | 今 |
| `dir` | `next` だけ | なし |

- `dir` なし: `at` 以前 14 日（`at` ちょうどを含む）で最新の完了したスナップショット
- `dir=next`: `at` 以後 14 日で最初のスナップショット。無ければ（`at` が最新より後）`at` 以前で最新のもの（画面は時刻が `at` より前なのを見て「これより新しいデータは無い」と分かる）
- スナップショットが無ければ空の 200
- 1 行目（メタ）: `<スナップショットの UNIX 秒>,<1 限月の最終取引日>,<1 限月の ATM>,<2 限月の最終取引日>,<2 限月の ATM>,<source>`。ATM が無ければ空。`source` はそのスナップショットの行の `ingest_run_id` が `legacy-fill114-` で始まれば `fill114`（#114 で約定から作った時点。#123）、それ以外は空
- 2 行目から（縦持ち。1 行 = 限月 × 行使価格 × call / put。`month, target_price, type` の昇順）: `month,type,target_price,iv,price,price_time,bid_iv,ask_iv,bid,ask,mid_iv,otm`
  - `month` は 1・2（そのスナップショットの最終取引日の最小 = 1 限月、最大 = 2 限月）、`type` は 1 = call・2 = put
  - `iv`・`bid_iv`・`ask_iv` は 0 以下を空にしたもの、`mid_iv` は両方あるときの平均、`otm` は OTM 合成に使う行なら 1（他は 0）。規則は上の「曲線」
  - `price_time`（約定の時刻）は UTC の UNIX 秒

### `/smile_data`（旧ビューアーと同じ形式）

`/smile_data`（引数なし）。今から 14 日以内の最新のスナップショットのスマイル。旧ビューアーとの見比べ（#54）のために形式を変えずに残している。

- 1 行目: `<スナップショットの UNIX 秒>,<1 限月 put の ATM の行使価格>`
- 2 行目から（行使価格の昇順）: `target_price,o1_call_iv,o1_call_price_time,o1_put_iv,o1_put_price_time,o2_call_iv,o2_call_price_time,o2_put_iv,o2_put_price_time`（`o1` = 1 限月、`o2` = 2 限月。`*_price_time` は UTC の UNIX 秒）
- スナップショットか ATM が無ければ 503

### `/data_gaps`（`/atm_iv` が読む）

`/data_gaps`（引数なし）。過去データの欠けの区間（表 `data_gaps` の全体。#123）。

- CSV の列は `prev_at,next_at,cause,status`（`prev_at` 昇順）。`prev_at`・`next_at` は欠けの前後のスナップショットの時刻（UTC の UNIX 秒）で、欠けているのはその間の分
- `cause` は `bug_format`・`bug_comma`・`no_change`・`unknown`、`status` は `none`・`filled`・`partial`（意味は [data-gaps.md](data-gaps.md)）。値が変わらず保存しなかった区間（`no_change` かつ `none`。欠けではない）は出さない
- 表が空なら空の 200

## 設定（環境変数）

`apps/viewer/src/optionchan_viewer/settings.py` の `from_env`。形が不正なら起動で失敗する。

| 環境変数 | 中身 | 既定 | 範囲・形 |
|---|---|---|---|
| `GCP_PROJECT` | BigQuery のプロジェクト ID | なし（必須） | プロジェクト ID の形 |
| `BQ_DATASET` | データセット | `optionchan_tokyo` | データセット名の形 |
| `BQ_LOCATION` | BigQuery のロケーション | `asia-northeast1` | 英数字と `-` |
| `MAX_BYTES_BILLED` | 1 クエリの `maximum_bytes_billed`（バイト数） | 1 GiB | 0 より大きく 10 GiB 以下 |
| `DAILY_BYTES_BILLED` | JST の 1 日にこのプロセスで課金されたバイト数の上限（#95）。超えたら API は 429 | 4 GiB | 0 より大きく 100 GiB 以下 |

- Cloud Run `viewer` には `GCP_PROJECT`・`BQ_DATASET`・`BQ_LOCATION` だけを渡している（`infra/prod/viewer.tf` の `env`）。`MAX_BYTES_BILLED`・`DAILY_BYTES_BILLED` は既定のまま。変えるときは `infra/prod/viewer.tf` の `env` に足す
- 1 日の上限はプロセス（Cloud Run のインスタンス）ごとに数え、JST の 0 時に数え直す。上限はクエリを出す前に見るので、超えた後の 1 本までは通る（`apps/viewer/src/optionchan_viewer/budget.py`）
- SQL は `apps/viewer/src/optionchan_viewer/sql/` にだけ置き、プロジェクト・データセットは起動時に設定から埋め、値はクエリパラメータで渡す。BigQuery の結果は 30 秒まで待つ
- ブラウザ用ライブラリ（Chart.js（`/smile`）・TradingView Lightweight Charts（`/atm_iv`））は `apps/viewer/package-lock.json` で固定し、イメージのビルドで同梱する（CDN を使わない）。応答には CSP などのセキュリティヘッダを付け、スクリプト・スタイルは同じオリジンの同梱ファイルだけ

## 費用

- Cloud Run は最小 0 インスタンス・リクエスト中だけ CPU。IAP（Cloud Run への直接設定）は追加費用なし。費用の大半は BigQuery のスキャン量
- 1 回のスキャン量の見積もり（要求ごと）・画面の取りすぎ防止・1 日の上限の考え方・1 日の量の確かめ方は runbook の「ビューアー（#13）」の「コスト」（[runbook.md の「ビューアー（#13）」](runbook.md#ビューアー13)）
- 分足（`/atm_iv_bars` の `1m`・`5m`・`15m`）と `/smile_snapshot` は生データ（`option_price_latest`）を読むので重い。1 時間足・日足の過去だけの範囲は 1 時間足の表だけを読むので軽い
